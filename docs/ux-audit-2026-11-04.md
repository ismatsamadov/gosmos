# Gosmos UX audit — 4 November 2026

The reported defect was the name field remaining on screen after the badge page. This pass
also reviewed launch, Mission Control, lessons, quizzes, review, documentation and Settings.
The corrections are split across `fix/gosmos-onboarding-focus`,
`fix/gosmos-lesson-navigation`, `fix/gosmos-responsive-panes`, and
`fix/gosmos-note-loading`. The notes branch builds on the navigation test harness.

## Changes

| Area | Problem | Correction |
|---|---|---|
| Opening | Alternative layouts created two name fields with one focus binding; the outgoing page also animated its native control. | A single control tree changes layout, clears editing before navigation, and removes page controls without a transition. Next, Back and Skip save the name; Return and Escape have explicit actions. The whole page scrolls in a short window. |
| Continue Learning | Before any lesson was completed, the dashboard could offer the last opened lesson but open the course's first unfinished one. | Continue opens the offered lesson. If an unseen opening intervenes, its destination is retained. |
| Narrow panes | Fixed split minimums could exceed the width left by a wide sidebar and inspector. | Code/readme and documentation panes stack below 580 pt. Split sizes stay within their container, including invalid saved fractions. A layout change retains the editor's identity. |
| Notes | The inspector accepted typing before the saved note loaded, which could replace the draft when the read completed. | Notes stay disabled until loaded. A failed load has an explanation and retry; retry does not replace an already loaded draft. |
| Completion | The last quiz had no continuation in its result footer; the toolbar offered no continuation at the end of a course or redo. | Results and toolbar offer Mission Control or Back to Review when there is no next lesson. |
| Optional lessons | Completing the last required lesson could show “Next chapter” even when the next lesson was optional in the same chapter. | The action says Continue Learning and retains the optional lesson. |
| Documentation | Go Documentation was also labeled Field Guide, colliding with the separate story glossary. | Its introduction and list consistently identify Go Documentation / Go Reference. |

## Verification of the combined changes

- Nine new app flow tests pass: opening/name persistence across relaunch, resume before a
  first completion, continuation through an unseen opening, final lesson, optional lesson,
  review return, rapid navigation, code/note persistence and note loading.
- Three new split-sizing tests pass, covering narrow containers, both pane bounds and
  invalid saved fractions.
- The full GosmosKit run passes 142 of 144 tests. The two process-group cleanup checks fail
  at their final `pgrep` assertion, as they did before these edits: process inspection here
  returns `Cannot get process list` rather than the expected “no matching process” exit code.
- Thirty-two editor text, selection, indentation and line-index tests pass. The native editor
  view run could not finish in this desktop-restricted session and was stopped.
- Go vet/tests pass for all seven packages. `make check` validates the 150-lesson Apogee
  library and the bundled Go reference.
- A release build without debug symbols succeeds. The app is assembled at
  `build/Gosmos.app`, including Go 1.27.3, and its deep/strict code-signature check passes.
  The default release's separate dSYM generation is blocked by this environment.

The actual graphical transition, keyboard focus, appearance, split dragging and native
editor undo still need a desktop check. A launch/snapshot could not run in this session;
automatic approval review also rejected unrestricted test execution because sandbox
escalation is disabled. The model tests establish persistence and navigation behavior,
not a visual reproduction of the name-field defect.
